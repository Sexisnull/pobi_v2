#### 【P1-2】`pw_requester._scope_path()` 回退分支：根目录写错 & 目录层级与注释不符

- **位置**：[pw_requester.py#L97-L104](file:///Users/kid/Desktop/02_Projects/pobi_v2/pobi_agent/tools/browser_automation/pw_requester.py#L97-L104)
- **问题**：
  1. L93 注释说"回退旧 `targets/<slug>/` 路径以兼容"，但 L103 代码写的是 `TASKS_ROOT / self.target_slug / ...`
     - `TASKS_ROOT` 是 `~/.pobi_v2/tasks`，故实际路径 = `tasks/<target_slug>/scope.<sid>.yaml`
     - 这既不是**新契约**（新是 `tasks/<task_id>/scope.<sid>.yaml`），也不是**旧契约**（旧据 PROJECT_GOAL 文字是 `targets/<slug>/<task_id>/scope.yaml`）
  2. 回退层级缺了 `<task_id>` 一级（即便要按 targets 兼容也应是 `<slug>/<task_id>/`，现在缺 task_id）
- **触发场景**：task_root 未注入时（CLI 单测 / fallback 路径 / 新路径注入失败的任何时刻）
- **修复建议**：与 PROJECT_GOAL 文字对齐（内核不感知 slug，统一用 task_id），直接删掉 target_slug 回退分支，让无 task_root 时统一返回 `None` 走 ScopePolicy 默认禁用安全策略：
  ```python
  def _scope_path(self) -> Optional[StdPath]:
      if not self.session_id:
          return None
      task_root = get_task_root()
      if task_root is not None:
          return StdPath(task_root) / f"scope.{self.session_id}.yaml"
      return None
  ```
  （理由：target_slug 分支是历史遗留的"半错兼容"，既不兼容新契约也不兼容旧契约，反而在 task_root 缺失时可能把 scope 文件写到一个无规律的位置，丢失并发隔离。安全优先：缺根 → 返回 None → 默认禁用策略 fail-closed。）

#### 【P1-3】`pw_requester.py` 命名空间污染：`from anyio import Path` 覆盖标准 Path 类

- **位置**：[pw_requester.py#L8-L9](file:///Users/kid/Desktop/02_Projects/pobi_v2/pobi_agent/tools/browser_automation/pw_requester.py#L8-L9) + 全文件
- **问题**：
  - 第 8 行 `from anyio import Path`（async 版本的 Path，返回协程）覆盖了内建语义上大家默认认知的 `pathlib.Path`
  - 第 9 行又 `from pathlib import Path as StdPath`
  - 后续任何新增代码如果写 `Path("foo")`，拿到的是 **anyio 的异步 Path**（`mkdir()`、`exists()` 都是 async），行为与 pathlib.Path 完全不同
  - 当前代码为规避该问题显式用了 `StdPath(task_root)` 包装，但文件级命名空间污染已存在，极易出 bug（且 bug 表现是调用了协程对象未 await，运行时才报错）
- **修复建议**：把 `from anyio import Path` 改为 `from anyio import Path as AsyncPath`（或更清晰的别名），任何需要异步文件 API 的地方明确写 `AsyncPath(...)`；全局保留 `pathlib.Path` 为默认同步 Path 语义。若此文件未用到 anyio.Path，直接删该 import。
