# 项目目标（Project Goal）

> 本文件定义 Pobi v2 的**目标与边界**：为什么做、服务谁、做到什么算成功、绝不做什么。
>
> **本文件不描述实现方式**，避免与其他心智文档重复维护：
> 架构与数据流 → `architecture.md`；技术选型决策与踩坑 → `constraints.md`；接口与数据模型 → `api-contract.md`；演进计划 → `roadmap.md`。
>
> 信息源：`README.md`、`pobi_v2/main.py`、`pyproject.toml` 及源码。**以源码为准，文档滞后即修正本文件。**

## 1. 问题陈述

上游 `pobi` / `deadend-cli` 已具备可用的 AI 自主渗透内核（多智能体协作、ADaPT 递归规划、Docker 沙箱验证），但它是**单机 CLI**：

| 痛点 | 后果 |
|---|---|
| 人必须守在终端 | 一次运行数小时到数十小时，人力被绑定 |
| 过程不落库、不可回放 | 跑完只剩结论，无法复盘、无法审计、无法向客户交代 |
| 结果不跨任务沉淀 | 同一目标重测，从零开始重复劳动 |
| 无授权范围硬护栏 | 越权风险全靠人自觉 |
| 无审批介入点 | 高危操作要么全放开、要么不能跑 |
| 单用户 | 无法团队协作，无法交付给安全服务团队 |

**结论**：内核可用，但形态限制了它只能个人把玩，进不了团队流程。Pobi v2 要解决的是**形态问题，不是内核能力问题**。

## 2. 目标用户与场景

| 用户 | 场景 |
|---|---|
| 授权渗透测试团队 | 承接授权项目，批量/周期性复测，需要留痕与报告交付 |
| 安全服务交付团队 | 把 AI 侦察作为人工测试的**前置环节**，缩短前期信息收集时间 |
| 靶场运营 / 教学 | 在受控靶场内做自动化演练与效果评估 |

**关键场景特征**：目标**已获书面授权**、范围**可显式声明**、结果**需要交付与追溯**。

## 3. 愿景（北极星）

> **让一次授权渗透测试，从「人守终端的一次性 CLI 运行」，变成「可托管、可观察、可干预、可追溯、可复用的团队服务」。**

内核能力沿用上游，平台层的全部增量价值都服务于这五个"可"。

## 4. 目标（按可判定的结果陈述，非功能罗列）

| ID | 目标 | 达成判定 |
|---|---|---|
| **G1 可托管** | 任务从创建到产出报告全程无人守终端 | 任务入队后由 worker 自主跑到终态，人工仅在审批点介入 |
| **G2 可观察** | 全过程实时可见、事后可回放、全程可审计 | 思考/工具调用/LLM/状态流转经 SSE 实时可见；断连可经 `/events` 游标回放；事件与审计留痕落库 |
| **G3 可干预** | 运行中人能介入，且介入语义明确 | 高危工具调用 fail-closed 审批（超时/拒绝均拦截）；支持取消、续跑、运行期下发指令 |
| **G4 可信** | 授权边界是硬约束，不靠人自觉 | 越权任务在**创建期**即被拒绝；执行期受 `ScopePolicy` 约束；高危操作默认拒绝 |
| **G5 可复用** | 同目标重测不重复劳动 | 侦察资产与 agent 经验按 `target_id` 跨任务沉淀，新任务启动期 seed 复用；已测端点/已尝试技术可查 |
| **G6 可交付** | 产出物可直接对客交付 | 结构化报告（Markdown/JSON）+ 审计日志，满足合规追溯 |
| **G7 可核算** | 成本与用量可解释 | 会话级 token 累计落库，按单价估算成本，运行期实时可见 |

**优先级**：G4 > G1 > G2 > G3 > G7 > G6 > G5。
理由：授权边界与托管能力是平台存在的底线；可复用（G5）是效率优化，当前以"死路收敛 + 续扫去重"的最小形态成立，深度形态见 `roadmap.md` P1–P4。

## 5. 非目标（明确不做）

> 本节用于防止过度设计与方向漂移。**新增需求若落入本节，默认拒绝，除非用户显式改变项目定位。**

- **N1 不面向未授权目标**：不提供绕过授权检查的能力，不为非授权场景优化。
- **N2 不追求替代人工渗透工程师**：定位是**放大器**（缩短信息收集与验证时间），不是替代者。不做"全自动出报告即可交付"的承诺。
- **N3 不做通用 LLM 应用平台**：不抽象成可配置任意 agent 的通用框架；工具与流程服务于渗透测试单一场景。
- **N4 不做计费/套餐体系**：成本统计仅供内部核算，不产品化商业化。
- **N5 不追求完全无人监督的自主性**：审批护栏是设计目标而非过渡态，不因"自动化率"指标而弱化 fail-closed。
- **N6 不做 0day 研究与武器化**：利用阶段的目标是**验证已识别漏洞的可利用性**，不是发现新漏洞或构造攻击武器。
- **N7 不将 `pobi_agent` 内核改写为平台专属实现**：内核以内嵌子包形式复用（uv workspace），保持上游可追溯；平台差异通过适配层收敛。

## 6. 成功度量

> **口径说明**：当前尚无自动化埋点，下表"现状"仅记录**已观测的个案**，不可外推为统计值。目标值仅填有依据的项，其余标 `TBD`——**待埋点后再设定，禁止凭感觉填数**。

| 指标 | 现状（个案观测） | 目标 | 口径 |
|---|---|---|---|
| 首次有效注入的工具调用轮数 | 35 次重抓、0 次真实注入（任务 `535aee8e`，DVWA sqli） | **< 10 轮** | 任务创建 → 首次真实注入请求之间的工具调用次数 |
| 高消耗零产出任务 | 存在（1600 万 token / 23.5h / 0 finding，`535aee8e`） | 收敛为个例，有熔断兜底 | 子 agent 内迭代已有 30min 子超时 + 足迹死路硬护栏（`is_surface_dead`） |
| 非终态残留任务数 | 未知（无埋点） | `TBD` | worker 每 5 分钟 `task-reconcile` 对账后的残留计数 |
| 续扫重复探测率 | 未知（无埋点） | `TBD` | 同目标新任务中，命中 `covered_assets` 仍重复探测的端点占比 |
| 审计可追溯性 | 已具备（事件落库 + 回放） | 保持 | 终态任务可完整回放时间线 |

## 7. 不可逾越的边界（红线）

违反以下任一项的改动，无论收益多大均不可接受：

1. **授权范围硬护栏**：`Target.scope` 注入 `ScopePolicy`，越权任务创建期拒绝，不依赖事后检查。
2. **高危操作 fail-closed**：审批超时/拒绝一律拦截；`yolo` 模式仅限授权靶场，且需显式开启。
3. **执行隔离**：命令执行经 Docker 沙箱（Kali）；无 Docker 时降级为受限的轻量扫描，**不得退化为宿主机裸执行**。
4. **认证会话不跨任务复用**：`auth_context/` 属时效敏感凭据，不入 PG 聚合层，每次任务重新认证。
5. **敏感数据最小化**：凭据加密存储（`auth_secret` Fernet）；本地产物聚合到 PG 时显式排除认证类文件。
6. **LLM 调用唯一入口**：所有 LLM 交互经 `pobi_v2/llm` 统一层，保证用量可核算、模型可替换、异常可归一。

## 8. 技术基线（不可协商的选型及理由）

> 版本与依赖清单以 `pyproject.toml` 为准，此表**只记录选型理由**（即"为什么不能随便换"）。

| 决策 | 理由 |
|---|---|
| 平台层 Python + FastAPI，内核 `pobi_agent` 内嵌子包（uv workspace，非 PyPI 安装） | 内核与平台同进程可复用其对象模型；内嵌保证上游可追溯，避免 fork 后无法合入上游修复 |
| 任务执行与 Web 进程分离（ARQ + Redis） | 任务时长达数十小时，绝不能占用请求上下文；分离后才可能实现取消、对账、跨进程用量合并 |
| 双层持久化：本地 sqlite（任务内高频写入）+ PostgreSQL（跨任务聚合、租户隔离） | 任务内写入高频且失败不应阻断主循环 → 本地旁路；跨任务复用与多租户隔离 → PG。**不合并为单层** |
| 事件总线 + SSE 实时推送 + 事件落库回放 | 长任务的可观察性只能靠流 + 回放双通道，缺一则断连即失明 |
| LLM 统一抽象层（LiteLLM + Instructor） | 用量核算、模型按角色分流（M9 预研）、异常归一的前提 |
| 前端 React + Vite 构建产物，nginx 静态托管 | 与后端完全解耦；开发期由宿主 Vite dev server 提供，不进 Docker |
| 迁移用 Alembic 显式版本链 | 需可追溯的 schema 演进历史；**不采用启动时幂等 DDL 的"重启即迁移"方式** |

## 9. 当前达成度

M1–M8+ 里程碑均已落地，平台形态的目标（G1–G4、G6、G7）**基本达成**；**G5 可复用**仍是主要缺口。

已知缺口指针（详见 `roadmap.md`）：

- **探索过程可检索化 P1–P4**（含 requester 重抓循环优化 R1–R3）——当前最高优先级
- **自定义工具注入 T1–T6**
- **扫描内核优化 S1–S6**
- **模型按角色分流 M9（预研）**
- **生产 CORS 收敛 A5**、`_is_safe_shell` 词法解析漏洞（第一层防御已知失守，待修复）
